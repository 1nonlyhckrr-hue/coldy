# Self-service role panels

`create` publishes one toggle button. `multi` publishes2-5 independently toggled distinct role buttons. Optional mappings need both role+label; roles must have only reviewed community permission flags and remain below current staff/bot hierarchy. All roles validated before one publication. Single-button custom IDs are kept unchanged after SQLitev16 migration; additional buttons store an index0-4 tied to stored mapping, exact server/channel/message. No emoji reactions, exclusive-role groups, live editing or automatic role cleanup are claimed.

Every create/list/disable checks current Manage Roles. Every click fetches current member, bot and chosen role, rejects changed dangerous permissions or unrelated messages, then rechecks panel active state after fetch. No pings, public localized Luna prompt and private result. Role changes are direct native calls with a short in-memory user mutex/cooldown. This is not durable per-click replay tracking; reconnect/interaction replay and uncertain role effects remain a release gate. A failed API action is not automatically retried. Membership is freshly read but concurrent staff role changes can still race.

Reserve all mappings atomically before publication. Current limit100 pending/active/uncertain panels per server. Pending startup states become uncertain, not republished. Disable frees a slot and old components remain visible but inactive. Unknown publication is not retried. No role revocation when disabling. Disabled historical records are not yet automatically pruned. Destination access is validated, but intended audience must be checked by staff.

200 full-project tests pass, six new tests cover mappings/click routing/bounds/privacy identity/current authority/locales/migration/recovery/cap. No real Discord publication or visual button check yet. Latest public checkpoint remains188 tests until next consolidated publication.
